# Обязательные расходы

## Для кого и зачем

Для семьи из трёх человек: самостоятельно завести обязательные платежи, заранее отложить под них деньги в расчёте семейного бюджета и видеть, что ещё нужно оплатить. Неоплаченные обязательства не исчезают при смене месяца.

Статус: шаги 1–2 закоммичены; по команде пользователя выполнен шаг 3 — повторения и перенос долгов. Проверки логики пройдены; ручная браузерная проверка ожидается. Шаг 4 не выполнялся. Коммит шага 3 — после отдельного «да».

## Что должно быть

### Свои платежи

- Добавить раздел «Обязательные платежи» с формой и списком. Ипотека, коммунальные услуги, кредит и секция ребёнка — только примеры: пользователь сам вводит название, готовых платежей нет.
- Это отдельные обязательства, а не категории с лимитами. Создание платежа не создаёт категорию, не задаёт её лимит и не меняет существующие категории или старые траты.
- У платежа есть название, сумма, дата оплаты по плану, периодичность и статус. Дата оплаты в форме означает срок; при отметке оплаты отдельно сохраняется фактическая дата.
- Название обязательно: 1–100 символов после удаления пробелов по краям. Названия могут совпадать; записи различаются постоянными идентификаторами.
- Сумма — положительное целое число до 9 007 199 254 740 991 ₸; пробелы между тысячами допустимы. Пустое значение, 0, отрицательное, дробное, нечисловое и слишком большое значение не сохранять; показать подсказку рядом с полем, сохранить остальной ввод.
- Дата обязательна и должна существовать в календаре. Разрешены прошлые и будущие даты; изначально сегодня по местному времени.
- Предлагаемые варианты периодичности первой версии: «Один раз», «Каждый месяц», «Каждые 3 месяца», «Каждый год». Период отсчитывается от первой указанной даты, а не от даты фактической оплаты.
- Новый платёж получает статус «Не оплачен». После сохранения он виден с названием, суммой, сроком, периодичностью и статусом; при отсутствии записей — «Пока нет обязательных платежей».

### Оплата и список

- В списке текущего месяца показать его платежи и все неоплаченные платежи прошлых месяцев. Отдельно дать доступ к оплаченным платежам прошлых месяцев; история не удаляется при смене месяца.
- Неоплаченные записи идут первыми, по сроку от раннего к позднему. При одинаковом сроке сохраняется порядок создания. Прошедший срок неоплаченной записи дополнительно отмечается словом «Просрочен», резерв сохраняется.
- «Оплатить» открывает подтверждение с названием, суммой и полем фактической даты, изначально сегодня. После подтверждения статус — «Оплачен», видна фактическая дата. Повторное нажатие не создаёт вторую оплату.
- Оплачивается вся сумма, частичные оплаты в эту версию не входят. Фактическая дата не может быть будущей; дата до планового срока допустима.
- Оплата учитывается в семейном расчёте один раз как отдельный обязательный расход. Обычная трата автоматически не создаётся; рядом с подтверждением пояснить, что повторно добавлять эту оплату в «Траты» не нужно.
- Для исправления ошибочной отметки доступно «Отменить оплату» с подтверждением: запись снова не оплачена, сумма возвращается в резерв, оплаченный расход исключается из месяца фактической оплаты. Отмена диалога ничего не меняет.
- Правка суммы, названия, срока, периодичности и удаление сохранённых обязательств в первую версию не входят. Эти ограничения явно указать рядом с формой до сохранения.

### Резерв и семейный бюджет

- По ответу пользователя резервировать деньги из доходов семьи за месяц. Основа — сумма сохранённых доходов с датой получения в текущем местном календарном месяце, включая будущие даты этого месяца согласно существующему учёту доходов. При отсутствии доходов основа равна 0 ₸; доходы других месяцев не переносятся.
- На обзоре и в разделе «Бюджет» добавить отдельный блок «Деньги семьи»: «Доходы месяца», «Обычные траты», «Оплачено обязательных», «В резерве» и «Доступно». Резерв — расчётное ограничение доступных денег, без перевода денег и без создания траты.
- Существующие общий бюджет из лимитов и его остаток сохранить как расчёт лимитов, с поясняющей подписью «Бюджет по лимитам». Не называть этот остаток доступными деньгами семьи: это отдельный показатель.
- В резерв входят все неоплаченные созданные платежи, включая просроченные. Для будущей первой даты резерв возникает сразу после сохранения; будущие повторения резервируются только после создания в соответствующем месяце.
- Доступно = доходы текущего месяца − обычные траты текущего месяца − обязательные оплаты с фактической датой в текущем месяце − весь неоплаченный резерв. Фильтры списков не влияют на этот расчёт. Добавление, изменение и удаление дохода сразу пересчитывают доступные деньги; при переносе его даты учитывается новый месяц.
- При оплате сумма исключается из резерва и учитывается как оплаченная по фактической дате. Платёж со сроком в прошлом месяце, оплаченный сейчас, относится к расходам текущего месяца. Если фактическая дата в прошлом месяце, меняется учёт того месяца, а текущий резерв освобождается.
- Старые показатели списка трат, его итог, категории и график обычных трат продолжают считать только обычные траты. На обзоре обязательные суммы показать отдельно с понятными подписями; не смешивать их незаметно с графиком и числом обычных записей.
- При нехватке денег платёж всё равно сохраняется и резервируется полностью. Доступная сумма может быть отрицательной; показать «Не хватает: … ₸». При ошибке чтения доходов показать доходы и доступно «—», сохранив известный резерв.
- Лимиты категорий не увеличиваются из-за обязательств; накопления не меняются. Незаданные лимиты не мешают расчёту денег семьи по доходам.

### Новый месяц и повторения

- Хранить отдельно правило повторения и каждый его платёж с собственными сроком, суммой и статусом. Оплата одного месяца не оплачивает остальные.
- При создании правила сразу создать первый платёж на указанную дату. Если начало в прошлом, создать также все положенные повторения до конца текущего местного месяца. До подтверждения показать число создаваемых платежей и общую сумму резерва, чтобы пользователь мог отменить действие.
- При наступлении нового месяца создать платежи, положенные в этом месяце по периодичности. Для разового ничего не создавать. Все прежние неоплаченные записи оставить вместе с их резервом; новые прибавить к нему.
- Если страницу не открывали несколько месяцев, при следующем открытии создать все пропущенные платежи до конца текущего месяца включительно, а не только последний. Ничего не создавать раньше первой даты.
- Сохранять исходный день: для 31-го в коротком месяце брать последний день, затем возвращаться к 31-му. Для ежегодного 29 февраля в невисокосном году брать 28 февраля; в високосном снова 29 февраля.
- Проверять смену местной даты при открытии, раз в минуту, при возвращении на вкладку и перед изменением платежей. Закрытая страница не работает в фоне; при открытии она догоняет календарь.
- Повторное открытие, F5, возврат часов назад и две вкладки не создают повтор одного правила на один плановый срок. Уникальность определяется правилом и датой; оплаченные записи тоже защищены от повторного создания.

### Хранение и вид

- Отдельный документ localStorage `family-obligations-v1`: версия, правила повторения и экземпляры платежей. Сроки и фактические даты хранить как YYYY-MM-DD, показывать как ДД.ММ.ГГГГ. Итоги рассчитывать из записей, не хранить отдельный изменяемый остаток.
- Создание правила с первыми экземплярами, догоняющее создание и изменение статуса сохраняются целиком: при ошибке нет половины операции, ложного успеха или потерянного резерва.
- Перед записью перечитывать документ; при поддержке Web Locks все изменения обязательств выполнять под общей блокировкой. Без Web Locks использовать одну вкладку для ввода; полная защита одновременной записи не гарантируется.
- Обновления другой вкладки перечитывать, сохраняя черновики. Устаревшее подтверждение оплаты или отмены не применять: попросить заново открыть актуальную запись.
- Ошибку чтения/записи показать явно. Непрочитанные суммы и зависимое «Доступно» — «—», без ложного нуля; повреждённые данные не затирать, ввод при неудаче оставлять. Доступные старые разделы продолжают работать.
- Русский интерфейс в текущем стиле, постоянные подписи полей, управление клавиатурой и видимый фокус. При подтверждении начальный фокус на «Отмена»; после закрытия вернуть его к действию платежа.
- Области нажатия не меньше 44 × 44 px. На ширине 375 px и при масштабе 200% длинные названия, даты, суммы и навигация доступны без перекрытий и горизонтальной прокрутки.

## Примеры

Сценарии независимы; проверять на тестовых данных без личных записей. Основу задавать поступлениями в разделе «Доходы», а не лимитами категорий.

1. **Свои названия.** Добавить «Ипотека» 100 000 ₸ на 30.11.2026 ежемесячно и «Секция Алисы» 20 000 ₸ на 28.11.2026 один раз. Две неоплаченные записи, резерв 120 000 ₸; категории и лимиты не добавились. После F5 записи и статусы на месте.
2. **Резерв и оплата.** В ноябре основа 300 000 ₸, обычные траты 5 000 + 2 500 + 12 000 = 19 500 ₸, резерв 120 000 ₸. Доступно 160 500 ₸. Оплатить ипотеку датой 28.11.2026: обязательных оплачено 100 000 ₸, резерв 20 000 ₸, доступно по-прежнему 160 500 ₸. Отмена оплаты возвращает исходные значения. Обычные траты остаются 19 500 ₸.
3. **Долг на следующий месяц.** Оставить оба платежа из примера 1 неоплаченными. При наступлении декабря добавится только декабрьская ипотека 100 000 ₸. Резерв 220 000 ₸: ноябрьские 120 000 ₸ и новые 100 000 ₸. Ноябрьские записи просрочены. После повторного открытия и F5 резерв тот же.
4. **Оплата старого долга.** В декабре оплатить ноябрьскую ипотеку 100 000 ₸ датой 02.12.2026. Резерв примера 3 становится 120 000 ₸, декабрьские обязательные оплаты — 100 000 ₸. Ноябрьский срок остаётся 30.11.2026, декабрьская ипотека не оплачена.
5. **Пропущенные месяцы.** Ежемесячный кредит 10 000 ₸ с 15.11.2026, все записи не оплачены. Следующее открытие 02.02.2027 создаёт декабрь, январь и февраль: всего четыре записи, резерв 40 000 ₸. Повторное открытие и вторая вкладка не добавляют пятую.
6. **Дни и периодичность.** Начало 31.01.2027 ежемесячно: сроки 31.01, 28.02, 31.03. Начало 31.01.2027 каждые 3 месяца: следующий 30.04.2027, затем 31.07.2027. Ежегодный с 29.02.2028: 28.02.2029, а в 2032 году снова 29.02.2032. В интерфейсе все даты с годом.
7. **Будущий старт.** В ноябре создать разовый платёж 15 000 ₸ на 10.01.2027: резерв сразу 15 000 ₸. Январь не создаёт его заново. Для ежегодного платежа на ту же дату следующее повторение только в январе 2028 года.
8. **Нехватка и ошибки.** Основа 25 000 ₸, траты 19 500 ₸, обязательство 10 000 ₸: доступно −4 500 ₸, «Не хватает: 4 500 ₸». Попытки добавить пустое название, сумму 0, abc или 12,5 ничего не меняют и показывают подсказку. При ошибке сохранения введённые данные остаются.
9. **Повторные действия.** Двойное нажатие при сохранении создаёт один платёж; два отдельных сохранения одинаковых полей — два разных обязательства. Оплата одного не меняет другое. Повторное подтверждение уже оплаченной записи не списывает сумму ещё раз.
10. **Изменение доходов.** В примере 2 увеличить доходы с 300 000 до 350 000 ₸ — доступно 210 500 ₸, резерв прежний. Перенести все доходы в другой месяц — доходы текущего месяца 0 ₸, доступно −139 500 ₸. Изменение лимитов категорий эти суммы не меняет. Ошибка чтения доходов даёт «—» вместо доступной суммы, а не нулевой доход.

## Ограничения

- Только HTML, CSS и JavaScript в этой папке; без npm, библиотек, внешних ресурсов и передачи данных в интернет. Страница работает при открытии index.html двойным щелчком.
- Не менять форматы старых хранилищ, не переносить автоматически существующие траты «Кредит» и «Ипотека» в обязательства. Не удалять их категории или лимиты.
- Без банковских переводов, уведомлений вне страницы, частичных оплат, ежедневных/еженедельных повторений, индексации сумм, редактирования и удаления правил. Расширение управления правилами требует отдельного согласования.
- Расчёты точные, включая большие общие суммы; деньги с пробелами и знаком ₸. Не показывать NaN, Infinity, дроби и экспоненциальную запись.
- README.md обновить после последнего шага. Новые файлы тестов не создавать. После каждого шага остановиться для ручной проверки; коммит и push только после отдельного «да» согласно AGENTS.md.

## Готово, когда

Основа семейного бюджета согласована — доходы семьи за месяц. Выполнение отдельных шагов отмечено в конце; полная приёмка функции ещё не завершена.

После реализации:

- Пользователь создаёт собственные обязательства со всеми пятью полями; неверный ввод отклоняется, данные и статусы сохраняются после F5.
- Все примеры дают указанные суммы и даты. Оплата и её отмена учитываются ровно один раз; обычные траты и категории не меняются.
- Неоплаченные обязательства сохраняют резерв между месяцами и годами; создаются все положенные повторения, без дубликатов и с верными короткими месяцами.
- Обзор и бюджет согласованно показывают отдельные обычные расходы, обязательные оплаты, резерв и доступную сумму. Фильтры на расчёт не влияют; неизвестные суммы не выданы за нули.
- Проверены ошибки хранилища, устаревшие действия, F5, обновление местной даты и вкладок; ограничения без Web Locks описаны.
- Проверка из AGENTS.md: добавить обычные траты 5 000, 2 500 и 12 000 → итог месяца 19 500 ₸; после F5 они на месте. Существующие доходы, накопления, фильтры и лимиты работают.
- На 375 px, 1280 px, при 200% и с клавиатуры доступны форма, список, подтверждения и навигация. README.md содержит описание и ручную проверку; непроверенное перечислено в отчёте.

### Как проверить будущий месяц руками без смены системных часов

Только в отдельном тестовом профиле браузера с копией проекта и ненужными данными: открытие копии в обычном профиле не гарантирует отдельное хранилище. Подготовить ноябрьские ипотеку 100 000 ₸ ежемесячно и секцию 20 000 ₸ один раз. Открыть инструменты разработчика (F12), вкладку «Консоль», выполнить этот код:

```javascript
window.Date = class extends Date {
  constructor(...args) {
    super(...(args.length ? args : ["2026-12-02T12:00:00"]));
  }
};
window.dispatchEvent(new Event("focus"));
```

1. Открыть «Обзор»: резерв 220 000 ₸. В платежах три записи, ноябрьские просрочены.
2. Выполнить последнюю строку ещё раз и открыть вторую вкладку с той же тестовой страницей: новых экземпляров нет. Для декабрьских расчётов во второй вкладке выполнить весь код и там. После F5 часы страницы снова реальные; для просмотра декабря выполнить код заново. Созданные тестовые платежи при этом остаются.
3. Оплатить ноябрьскую ипотеку датой 02.12.2026: резерв 120 000 ₸, оплачено в декабре 100 000 ₸. Для пропущенных месяцев и коротких месяцев использовать отдельные тестовые данные из примеров 5–6 и заменить дату в коде на нужную. Для возврата реального времени страницы достаточно F5; системные часы этот код не меняет.
